# ProfIT — групповое тестирование

Преподаватель создаёт сессию по своему направлению, выбирает блоки заданий и число мест. Участники открывают общую ссылку, вводят ФИО, номер участника и группу, разрешают показ всего экрана и ждут общего старта. Преподаватель задаёт длительность, например 120 минут, и запускает задания одновременно у всех.

## Запуск

Нужен **Node.js 22.9+**.

```bash
npm install
cp .env.example .env
# Задайте TEACHER_PASSWORD в .env
npm run dev
```

Интерфейс: `http://localhost:5173`. API: порт 3001. Логин по умолчанию — `teacher`, пароль — из `.env`. Если пароль не настроен, сервер выводит случайный временный пароль в терминал; при перезапуске он меняется. Пароль не включается в клиентскую сборку.

`npm run dev` запускает клиент и API. Если Vite был запущен раньше, остановите его перед этой командой. В другом случае можно оставить Vite и запустить только `npm start` для API. Vite использует API на порту 3001; при изменении `API_PORT` измените также `vite.config.js`.

```bash
npm test       # интеграционные проверки HTTP API и событий
npm run build # сборка клиента
npm start     # API + раздача dist на порту 3001
```

`npm run preview` проверяет только статическую сборку, без API. Для работы приложения используйте `npm start`.

## Преподаватели и направления

По умолчанию преподавателю доступны HTML/CSS, JavaScript, Python, C# и английский. Для отдельных учётных записей укажите `TEACHERS_JSON` в `.env` (пример в `.env.example`). У каждого преподавателя свои сессии и разрешённые направления; ограничения проверяет сервер. Сессия входа сохраняется на 24 часа в HttpOnly cookie.

При создании можно выбрать один или несколько блоков теории и практики. Банк заданий уже существовал в проекте; теперь его загружает только сервер, правильные варианты не отправляются участникам.

- HTML/CSS: редакторы HTML и CSS, изолированное превью.
- JavaScript: редактор и изолированный запуск с лимитом 3 секунды, без доступа к данным сайта и сети.
- Python, C#: редактор и сдача исходного кода; среда выполнения пока не подключена.
- Английский: грамматика, чтение и письменная практика. Голосовые задания старого демо в новый сценарий не включены.
- Теория оценивается сервером; практику преподаватель проверяет и оценивает вручную от 0 до 100 с комментарием.

## Проведение сессии

1. Преподаватель входит по паролю и создаёт сессию.
2. Общая ссылка `/join/<id>` открывается на компьютерах аудитории. Переходить на главный экран участникам не требуется.
3. Каждый вводит ФИО, уникальный в пределах сессии номер участника и группу, подтверждает согласие на контроль экрана. Номер — идентификатор участника, не обязательный телефон.
4. На рабочем месте видны задания, но поля заблокированы. Участник нажимает «Подключить весь экран» и выбирает весь монитор.
5. В кабинете одновременно видны трансляции всех участников в сетке, количество регистраций, подключение к серверу, текущее задание, события контроля и состояние записи экрана. Начать можно после готовности всех зарегистрированных участников, в том числе с неполной группой.
6. Преподаватель задаёт от 1 до 480 минут и нажимает старт. Регистрация закрывается. У всех одинаковое время завершения.
7. Ответы автоматически сохраняются на сервер. При обрыве связи редакторы блокируются, несохранённый черновик остаётся в браузере. После восстановления связи и экрана сохранение повторяется; дедлайн не продлевается.
8. Участник сдаёт работу сам либо сохранённые ответы сдаются автоматически по дедлайну. Преподаватель также может завершить всю сессию досрочно.
9. Нажмите на экран участника: увеличенная трансляция и полный журнал событий отображаются рядом. Есть поиск по журналу, фильтр событий контроля, время до секунды, история решений и ручная оценка. На вкладке «Записи» фрагменты воспроизводятся последовательно и скачиваются отдельно. Полный журнал вместе с работой и историей можно скачать в JSON.

При обновлении страницы участник узнаётся по cookie в том же браузере. После обновления нужно заново разрешить экран. Повторная регистрация с тем же номером на другом компьютере запрещена. Перенос рабочего места/сброс регистрации через кабинет пока не реализован.

## Что адаптировано из INTERVIEW

Источник: `INTERVIEW/InterviewLabBack/app/services/proctoring.py`, маршруты `api/routes/proctoring.py` и описание `INTERVIEWLAB_SHORT.md`.

Сохранена схема «участник — наблюдатель»: экран передаётся напрямую по WebRTC, сервер авторизует участников и пересылает offer/answer/ICE. В этом приложении сигнализация и состояния идут через HTTP + SSE вместо WebSocket; это новая реализация для текущего React/Node проекта, а не запуск исходного FastAPI/MongoDB приложения.

Перенесены подходы к live-наблюдению, журналу событий, истории ответов и записи экрана. Камера, микрофон, распознавание лиц/объектов и аудиоаналитика не подключаются. AI-генерация и AI-оценка InterviewLab не перенесены: в этом сценарии задания выбирает и практику проверяет преподаватель.

Прокторинг фиксирует уход и возврат на вкладку, потерю и возврат фокуса окна, вход и выход из полного экрана, открытие задания, длину вставленного текста, сохранение ответов, отключение экрана и разрыв связи. Сервер также журналирует старт, сдачу, оценку и сохранение каждого фрагмента видео. Содержимое буфера обмена отдельно не собирается. История хранит изменения ответов после автосохранения, а не каждое нажатие клавиши. События не означают автоматического обвинения в списывании. Обычный сайт не может запретить запуск других приложений или защититься от подмены браузерной телеметрии.

Запись выполняется на компьютере участника независимо от того, открыт ли кабинет преподавателя и какую карточку он просматривает. Начинается после общего старта и сохраняется на сервер отдельными воспроизводимыми WebM-фрагментами примерно по 20 секунд. При обычной сдаче отправляется последний фрагмент; при аварийном закрытии вкладки текущий фрагмент может потеряться. Неудачные загрузки повторяются четыре раза, затем участник видит предупреждение. На сетке видны число сохранённых фрагментов, запись, прерывание и ошибки; ошибки последнего фрагмента сохраняются в журнале даже после сдачи работы. Автоматического удаления записей пока нет.

## Работа на нескольких компьютерах

На компьютерах аудитории должен быть доступен **один сервер** и один адрес сайта. Сервер хранит комнаты, дедлайны, ответы и события; `localStorage` используется только для аварийных черновиков. SSE обновляет состояние без перезагрузки страницы.

Для показа экрана браузеру нужен **HTTPS** и действие участника. `http://localhost` допускается для разработки, но обычный `http://192.168.x.x` на соседнем компьютере не подходит. Настройте домен/сертификат, которому доверяют компьютеры аудитории, и обратный прокси к порту 3001. В `.env` включите `SECURE_COOKIES=true` при HTTPS.

Пример location для Nginx внутри уже настроенного HTTPS server:

```nginx
client_max_body_size 12m;
location / {
    proxy_pass http://127.0.0.1:3001;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 3600s;
}
```

WebRTC в одной сети может использовать прямое соединение. При просмотре всей аудитории преподаватель получает отдельный видеопоток от каждого участника; пропускная способность сети и возможности компьютера должны соответствовать размеру группы. При NAT, изоляции клиентов Wi-Fi и разных сетях настройте свой STUN/TURN через `ICE_SERVERS_JSON`; пример есть в `.env.example`, а исходный конфиг coturn — в `INTERVIEW/InterviewLabBack/deploy/turnserver.conf.example`. Конфигурация ICE доступна только авторизованным участникам сессии. Используйте отдельные ограниченные TURN-учётные данные.

Справка: [захват экрана и ограничения браузера](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia), [соединение WebRTC и ICE](https://webrtc.org/getting-started/peer-connections).

## Хранение и эксплуатация

- `server/data/state.json`: сессии, авторизация, участники, ответы, оценки, события и индекс записей; запись атомарной заменой файла.
- `server/data/history/`: история ответов в отдельных append-only JSONL-файлах; загружается при открытии вкладки «История» или экспорте работы, не пересылается с каждым обновлением.
- `server/data/recordings/`: WebM-фрагменты, доступные только владельцу сессии через авторизованный API.
- `.env` и `server/data` исключены из Git. Для другого постоянного диска задайте `DATA_DIR`.
- Токены хранятся на сервере в виде SHA-256-хешей; пароль сравнивается через scrypt и constant-time сравнение. JSON конфигурации преподавателей хранится в окружении сервера.
- Запускайте **один процесс API** на каталог данных: SSE-комнаты находятся в памяти. Это файловый backend для одной установки; для нескольких процессов/большой нагрузки нужны БД, общая сигнализация и объектное хранилище.
- Состояние и дедлайн переживают перезапуск. Во время остановки сервера ответы не принимаются; при восстановлении истёкшие сессии автоматически завершаются.
- Требуются резервные копии каталога данных и контроль места под записи. При 500 кбит/с двухчасовая запись одного экрана может занять около 450 МБ; фактический размер зависит от браузера и изображения.

## Структура

```text
server/app.js           HTTP API, авторизация, SSE, жизненный цикл, записи
server/catalog.js       адаптер существующих банков заданий
server/app.test.js      интеграционные тесты
server/index.js         конфигурация и запуск сервера
scripts/dev.js          совместный запуск API и Vite
src/exam/Teacher.jsx    кабинет, создание сессии, наблюдение и проверка
src/exam/Participant.jsx регистрация, задания, автосохранение, экран
src/exam/ScreenWall.js  независимые соединения со всеми участниками
src/exam/ScreenWall.jsx сетка трансляций и повторное использование потоков
src/exam/EventLog.jsx   живой журнал, поиск и фильтр событий контроля
src/exam/Recordings.jsx воспроизведение и скачивание архива
src/exam/Proctor.js     WebRTC и очередь ICE
src/exam/useRoom.js     серверные состояния и переподключение SSE
src/exam/exam.css       интерфейс кабинета и рабочего места
```

Старые компоненты демо и `src/lib/storage.js` оставлены как исходные материалы, но новый `App.jsx` их не использует. Содержимое `INTERVIEW` не изменяется.
