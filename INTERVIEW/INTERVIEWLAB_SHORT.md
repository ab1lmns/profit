# InterviewLab — короткая шпаргалка

## Проект одним предложением

InterviewLab — сервис для технического отбора разработчиков: HR создаёт тест, кандидат решает его в браузере, система записывает ход работы и нарушения, а AI формирует итоговый отчёт.

## Как всё работает

1. HR регистрируется и создаёт технический тест.
2. Задания можно написать самому, взять из библиотеки или сгенерировать через Gemini.
3. HR отправляет кандидату ссылку.
4. Кандидат даёт доступ к камере, микрофону и экрану.
5. Кандидат пишет код в браузерном редакторе Monaco.
6. Система сохраняет историю кода, вставки, переключения вкладок, сигналы камеры и запись экрана.
7. После отправки Gemini анализирует код и события.
8. HR получает балл, рекомендацию, код, replay, нарушения и видеозапись.

Главная идея: обычный тест показывает только ответ, InterviewLab показывает ещё и **как кандидат получил этот ответ**.

|---|---|
| React 19 | Весь интерфейс HR и кандидата |
| TypeScript | Типы и меньше ошибок в JavaScript-коде |
| Vite | Сборка и быстрый запуск frontend |

| Pyodide + Web Worker | Запуск Python прямо в браузере, отдельно от интерфейса |
| Sandpack | Запуск и preview React/JavaScript/TypeScript |

### Backend

| Технология | Для чего используется |
|---|---|
| Python + FastAPI | Сервер и REST API |
| Pydantic | Проверка входящих данных и ответов Gemini |
| Beanie | Связь Python-объектов с MongoDB |
| MongoDB | Пользователи, компании, тесты, кандидаты, события и отчёты |
| JWT | Авторизация HR и защита запросов |
| bcrypt | Безопасное хеширование паролей |
| SMTP | Отправка приглашений по email |
| Gemini API | Генерация заданий и анализ результатов кандидата |

### Прокторинг и запись

| Технология | Для чего используется |
|---|---|
| TensorFlow.js | Запуск компьютерного зрения в браузере |
| COCO-SSD | Обнаружение телефона и других объектов |
| BlazeFace/FaceDetector | Проверка наличия и количества лиц |
| WebSocket | События в реальном времени и связь для live-наблюдения |
| WebRTC | Прямая видеотрансляция кандидат → HR |
| MediaRecorder | Запись экрана, камеры и микрофона |

Важно: live-видео идёт напрямую через WebRTC, но итоговая запись загружается на backend и хранится 30 дней.

## Что именно отслеживается

- кандидат ушёл с вкладки;
- лицо исчезло;
- появилось несколько людей;
- появился телефон;
- камера или демонстрация экрана выключилась;
- возможная смена человека;
- разговоры и постоянный посторонний звук;
- большие вставки кода;
- вся история изменения файлов.

Это не «доказательство списывания». Система создаёт risk score и показывает HR подозрительные моменты для проверки.

## Как оценивается кандидат

- Gemini даёт `technical score` за качество решения.
- Из событий прокторинга считается `integrity score`.
- Общий балл примерно равен техническому баллу минус штраф за риск.
- Затем система выдаёт рекомендацию: strong hire, hire, consider или reject.

Gemini сейчас делает статический анализ финального кода. Он не запускает все языки на сервере. Реально запускать в MVP можно Python и React/JS/TS.

## Самые вероятные вопросы жюри

### В чём проблема?

HR не всегда может проверить технический уровень, поэтому Team Lead тратит время на слабых кандидатов.

### В чём ваше решение?

Практический тест с редактором кода, replay, прокторингом, записью и AI-отчётом в одной системе.

### Кто ваш клиент?

Малые и средние IT-компании Казахстана, которым нужен первичный отбор разработчиков.

### В чём отличие от HackerRank и Codility?

Локальная цена, русский интерфейс, простота для небольших компаний и объединение replay, прокторинга, записи и AI-отчёта в одном процессе.

### Как AI определяет списывание?

AI не выносит приговор. Браузер фиксирует телефон, лица, вкладки, экран, звук и вставки, после чего HR проверяет подозрительные моменты.

### Что делает Gemini?

Создаёт черновики заданий и после теста формирует структурированный анализ кода и событий.

### Можно ли обмануть прокторинг?

Абсолютной защиты нет. Система повышает сложность обмана и собирает доказательства, но окончательное решение принимает человек.

### Где хранятся данные?

Основные данные находятся в MongoDB, записи сейчас на файловой системе backend. Срок хранения записи — 30 дней.

### Как защищены данные?

Пароли хешируются bcrypt, HR работает через JWT, данные разделены по компаниям, перед тестом запрашивается согласие. Для production ещё нужны шифрованное object storage и полноценный security-аудит.

### Какие языки поддерживаются?

Редактировать можно разные языки, но запуск в текущем MVP полноценно сделан для Python и React/JavaScript/TypeScript.

### Как считается итоговый балл?

Берётся техническая оценка и уменьшается с учётом риска прокторинга. Это вспомогательный балл, не автоматическое решение о найме.

### Сколько стоит один тест?

По расчётам проекта переменные расходы — до 220 тенге на тест: AI, запись, сервер и email.

### Почему компании будут платить?

Стоимость теста намного меньше часа Team Lead, который иначе вручную проводил бы первичное интервью.

### На какой стадии проект?

Работающий end-to-end MVP. Для production ещё нужны усиление безопасности, серверный запуск языков, облачное хранение и дополнительные пилоты.

### Какие планы развития?

Пилоты с компаниями, казахский язык, ATS-интеграции, больше языков, hidden tests, облачное хранение и улучшение точности анализа.

## Что нельзя говорить

- Не «AI точно ловит мошенников», а «система показывает риск-сигналы».
- Не «поддерживаем запуск всех языков», а «сейчас Python и React/JS/TS».
- Не «видео нигде не хранится», а «live идёт P2P, запись хранится 30 дней».
- Не «AI сам решает, кого нанять», а «последнее решение принимает HR или Team Lead».
- Не «продукт полностью готов к enterprise», а «это работающий MVP для пилотов».

## Что выучить наизусть

1. HR создаёт тест → кандидат пишет код → система записывает процесс → Gemini делает отчёт.
2. React — интерфейс, FastAPI — сервер, MongoDB — данные, Gemini — AI.
3. Monaco — редактор, Pyodide — Python, Sandpack — React/JS/TS.
4. TensorFlow.js и модели лица/объектов — прокторинг.
5. WebRTC — live-видео, MediaRecorder — запись.
6. Главная ценность — экономия времени Team Lead.
7. Система даёт сигналы, а не обвиняет кандидата.
8. Это рабочий MVP, а не законченный enterprise-продукт.
